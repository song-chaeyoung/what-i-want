# 뭐갖고싶어 Visual System Design

최초 작성일: 2026-05-14
최종 코드 대조일: 2026-10-30
추가 코드 대조일: 2026-11-04 (홈 카피·CTA만)

이 문서는 초기 시각 방향과 현재 구현의 관계를 설명합니다. `설계 의도`는 유지하려는 방향이며, `현재 구현`은 2026-10-30의 전체 코드 대조와 위 범위의 추가 정적 대조를 기준으로 합니다. 현재 구현을 기록한 것만으로 모든 상태·대비·접근성이 검증되었거나 권장 규칙으로 확정된 것은 아닙니다.

## Purpose

`뭐갖고싶어`의 디자인은 공개 공유 경험과 관리자 운영 경험을 분리합니다.

공개 페이지는 친구에게 보내는 생일 카드처럼 보여야 합니다. 귀엽고 가볍고, 링크를 받은 사람이 바로 선물 목록을 훑고 마음을 남기고 싶어야 합니다.

관리자 화면은 반복 입력과 상태 관리를 위한 운영 UI입니다. 공개 페이지의 장식성을 그대로 가져오지 않고, 조용하고 읽기 쉬운 화면으로 유지합니다.

## Core Decision

설계 의도는 `Public Pixel / Admin Calm`입니다. `Public Pixel`은 기본 브랜드 인상이며, 모든 공개 테마를 픽셀 모양으로 고정한다는 뜻은 아닙니다.

공개 화면:

- `pixel_y2k`를 기본 브랜드 인상으로 사용합니다.
- 기본 `pixel_y2k`에는 두꺼운 테두리, 오프셋 그림자, 파스텔 면, 스티커 라벨, 작은 픽셀 장식을 씁니다. 다른 두 테마는 같은 정보 구조에 각자의 색·모서리·그림자·폰트를 적용합니다.
- 친구끼리 공유하는 생일 위시리스트처럼 장난스럽게 보이되, 선물명, 금액, 진행률, 상품 링크는 빠르게 읽혀야 합니다.

관리자 화면:

- 생일자가 고른 공개 테마를 관리자 shell과 작업 화면 전체에 적용하지 않습니다.
- 배경은 밝은 뉴트럴, 입력/리스트는 낮은 대비의 선과 작은 그림자로 정리합니다.
- 선물 등록, 수정, 삭제, 메시지 확인처럼 반복 작업이 많은 화면이므로 장식보다 밀도와 안정감을 우선합니다.
- 현재 구현에는 첫 진입 안내와 생일 축하 연출이 있습니다. 첫 진입 안내는 브랜드 테두리·그림자와 테마 미리보기를 사용하는 명시적 예외입니다. 근거: [관리자 UI](../../../app/admin/admin-ui.tsx), [첫 진입 안내 설계](2026-07-22-admin-first-entry-guide-design.md#6-시각-디자인), [안내 구현](../../../app/admin/admin-guide-dialog.tsx), [생일 연출](../../../app/admin/birthday-confetti.tsx).
- 로그인·온보딩은 공개 테마 선택을 따르지 않지만, 현재 고정 픽셀 브랜드 장식을 사용합니다. `Core UI` 분류가 모든 화면의 장식 제거를 뜻하지는 않습니다. 근거: [로그인](../../../app/login/page.tsx), [온보딩](../../../app/onboarding/page.tsx).

## Visual Tokens

다음 표는 초기 브랜드 팔레트입니다. 실제 공개 테마별 역할과 값은 [public-themes.css](../../../app/public-themes.css)의 `--pub-*`, 공통·관리자 값은 [globals.css](../../../app/globals.css)를 확인합니다. 특히 카드 내부 제목은 `--pub-ink`를 쓰며 헤더 제목 색과 구분됩니다.

| Token | Value | Usage |
| --- | --- | --- |
| Ink | `#171717` | 주 텍스트, 두꺼운 테두리 |
| Deep Purple | `#4c1d95` | 공개 페이지 헤드라인, 강조 잉크 |
| Teal | `#0f766e` | 진행률, 성공 상태, 보조 CTA |
| Orange | `#f97316` | 선물 아이콘, 주요 포인트 |
| Yellow | `#fef3c7` | 히어로/스티커 배경 |
| Mint | `#ccfbf1` | 카드 이미지 fallback, 보조 면 |
| Blush | `#ffe4e6` | 공개 페이지 배경 포인트 |
| Paper | `#fffdf7` | 카드 내부 배경 |
| Neutral Line | `#d1d5db` | 관리자 UI 경계 |

현재 형태:

- `pixel_y2k` 공개 카드 border: `2px solid #171717`
- `pixel_y2k` 카드 shadow: `6px 6px 0 #111827`. 큰 그림자 토큰은 `8px 8px 0 #111827`이지만 현재 공개 상단은 카드가 아닌 전체 너비 헤더입니다.
- 관리자 카드 border: `1px solid #d1d5db`
- `pixel_y2k` 카드·버튼·입력 radius는 `4px`, `mono_bw`는 `0`, `soft_pastel` 카드는 `22px`, 버튼은 `16px`, 입력은 `14px`입니다. 초기의 모든 공개 카드 `4px` 이하 규칙을 다른 테마에 확대 적용하지 않습니다.
- 그라데이션 orb, bokeh, 추상 SVG 배경을 사용하지 않는 것은 기존 설계 의도입니다.

타이포:

- 일반 본문은 sans 계열이며 픽셀 제목·라벨·버튼은 로컬 MonaS12 Bold(`700`)를 사용합니다. 비픽셀 테마는 sans 계열을 사용합니다. 근거: [폰트 등록](../../../app/fonts.ts), [공개 테마](../../../app/public-themes.css).
- 공개 페이지 본문은 주로 14-16px이며, 제목 크기는 테마 토큰과 반응형 클래스로 결정됩니다. 모든 제목이 `font-black`인 것은 아닙니다.
- 관리자 일반 라벨·버튼은 주로 `font-semibold`이며 지표에는 `font-extrabold`도 사용합니다. 제목 크기를 과하게 키우지 않는 것은 설계 의도입니다. 근거: [관리자 UI](../../../app/admin/admin-ui.tsx).
- viewport width 기반 글자 크기를 사용하지 않는 것은 기존 설계 의도입니다.

현재 UI 구현은 공개 `.pub-*` 클래스, 관리자 `admin-ui.tsx`의 공통 컴포넌트·클래스, `components/ui`의 shadcn/Radix 기반 UI를 함께 사용합니다. 별도 디자인 시스템 패키지는 없으며, 이미 도입된 UI를 없는 것으로 가정하지 않습니다. 근거: [의존성](../../../package.json), [생일 선택 UI](../../../app/onboarding/birthday-picker.tsx), [공통 버튼](../../../components/ui/button.tsx).

## Page Rules

### Home

첫 화면은 제품명과 실제 공개 페이지 미리보기가 보여야 합니다.

- H1: `친구들과 함께하는 생일 선물 펀딩`
- 보조 문구: 선물과 목표 금액을 정해 링크로 공유하고, 친구가 메시지를 남기거나 안내 계좌로 마음을 보탤 수 있다는 설명
- 우측/하단 미리보기: 별도 작성된 고정 샘플 카드입니다. `/sample`은 실제 공개 화면의 `PublicWishlistView`를 데모 모드로 재사용합니다.
- CTA: 비로그인은 `내 위시리스트 만들기`, 로그인 후 온보딩 미완료는 `위시리스트 만들기 계속하기`, 온보딩 완료는 `내 위시리스트 관리하기`
- 샘플 진입 CTA: `펀딩 예시 보기` → `/sample`

근거: [홈과 계정 CTA](../../../app/page.tsx), [샘플](../../../app/sample/page.tsx), [온보딩 상태 조회](../../../src/lib/onboarding/repository.ts).

### Public Wishlist `/wishlist/[slug]`

공개 페이지는 브랜드 감성을 가장 강하게 보여주는 화면입니다.

- 상단은 생일 카드 포스터처럼 구성합니다.
- 타이틀은 저장된 `wishlist.title`을 보여줍니다. 온보딩 기본 제목은 `{displayName}님의 위시리스트`입니다.
- 요약 박스는 `선물`, `모인 마음`처럼 감성적인 라벨을 씁니다.
- 선물 카드는 이미지 영역, 상태 스티커, 선물명, 설명, 진행률, 상품 링크를 한 번에 읽게 합니다.
- 이미지가 없으면 테마별 선물 그래픽 fallback을 둡니다. 픽셀·선형·부드러운 그래픽 중 선택 테마에 맞는 하나를 표시합니다.
- `hidden` 선물은 노출하지 않습니다.
- 메시지만 보내기와 선물별 마음 보내기 폼은 Server Action으로 제출합니다. 금액 참여는 실제 송금 확인 없이 기록과 진행률에 반영되며, 성공 후 등록 계좌를 안내합니다. 이 화면에서 결제나 송금은 실행하지 않습니다.

근거: [공개 화면](../../../components/public-wishlist-view.tsx), [온보딩 기본값](../../../src/lib/onboarding/service.ts), [공개 조회](../../../src/lib/public-wishlist/service.ts), [참여 Action](../../../app/wishlist/[slug]/actions.ts), [참여 저장](../../../src/lib/public-participation/repository.ts).

### Public Empty / 404

현재 빈 상태는 조회된 위시리스트의 선택 테마 안에 표시합니다. 404·로딩·오류 경계는 위시리스트 테마를 전달받지 않으며 `.pub-page` 기본값인 `pixel_y2k`로 표시합니다.

- 빈 상태: `아직 공개된 선물이 없어요`
- 404: `위시리스트를 찾을 수 없어요`
- 404 CTA는 `처음으로`, 오류 경계는 `다시 시도`입니다. 빈 목록에서도 계좌·메시지·생성 CTA가 있는 공개 화면의 나머지 구조는 유지됩니다.

근거: [공개 화면](../../../components/public-wishlist-view.tsx), [404](../../../app/wishlist/[slug]/not-found.tsx), [로딩](../../../app/wishlist/[slug]/loading.tsx), [오류 경계](../../../app/wishlist/[slug]/error.tsx), [기본 토큰](../../../app/public-themes.css).

### Admin

관리자 화면은 기능 중심으로 유지합니다.

- 상시 작업 화면에는 공개 테마를 적용하지 않습니다. 첫 진입 안내의 장식 예외는 위 Core Decision을 따릅니다.
- 상단 nav, 입력 폼, 리스트 카드의 간격과 버튼 스타일만 정리합니다.
- 상태 라벨은 작고 명확하게 유지합니다.
- 링크·버튼·입력의 현재 위계는 [관리자 UI](../../../app/admin/admin-ui.tsx)와 각 화면을 확인합니다. 공개 미리보기 링크만 유일하게 강조된다는 초기 설명은 현재 구현의 제한 조건이 아닙니다.
- 선물·설정 폼은 관리자 Route Handler로 네이티브 POST하며, 공개 참여 Server Action과 제출 경로가 다릅니다. 근거: [선물 폼](../../../app/admin/wishes/page.tsx), [설정 폼](../../../app/admin/settings/page.tsx), [선물 POST](../../../app/api/admin/wishes/route.ts).

## Copy Tone

카피는 짧고 친구 같은 말투를 씁니다.

기존 방향을 설명하는 예시 문장입니다. 실제 화면의 최신 문구는 [공통 카피](../../../src/lib/design/copy.ts), [상태 라벨](../../../src/lib/wish-item/status.ts), [공개 화면](../../../components/public-wishlist-view.tsx)을 확인합니다. 예시를 현재 UI 문구 전체로 간주하지 않습니다.

- `생일 축하해. 뭐 갖고 싶어?`
- `받고 싶은 선물을 링크 하나로 모아 공유해요.`
- `{name}님이 갖고 싶은 것들`
- `마음 모으는 중`
- `상품 보기`
- `내 위시리스트 만들기`
- `위시리스트 만들기 계속하기`
- `내 위시리스트 관리하기`

피할 문장:

- 지나치게 SaaS처럼 보이는 `관리 솔루션`, `운영 대시보드`
- 공개 페이지에서 딱딱한 `목표 금액`, `누적 금액`만 단독으로 쓰는 표현
- 기능 설명을 화면에 길게 늘어놓는 문장

## Implementation Status

초기 구현 순서에는 토큰 정리, 한글 복구, 공개 픽셀 테마, 홈 미리보기, 관리자 위계 정리, 메시지·OG 확장이 포함되어 있었습니다. 이를 현재의 미완료 작업 목록으로 재사용하지 않습니다.

- 현재 존재: 공통/공개 토큰, 세 공개 테마, 홈 미리보기, 관리자 공통 UI, 공개 참여 폼, 기본·개인별 OG. 근거: 위 구현 링크와 [토큰 통합 계획의 완료 기록](../plans/2026-06-01-public-theme-token-integration.md).
- 설계와 남은 차이: 개인별 OG의 선택 테마 반영. 현재는 고정 브랜드 스타일입니다.
- 검증 범위: 이 문서의 갱신은 코드 정적 대조입니다. [공개 계약 테스트](../../../src/lib/design/public-theme-contract.test.ts), [관리자 계약 테스트](../../../src/lib/design/admin-theme-contract.test.ts), [샘플 테마 E2E](../../../tests/sample/valid-themes.spec.ts)는 존재하지만 이번 문서 갱신에서 실행하지 않았습니다.
- 접근성·모션 기준은 [첫 진입 안내 설계](2026-07-22-admin-first-entry-guide-design.md#7-단계-전환과-모션)에 기능별로 존재합니다. 공개 폼의 포커스·오류·대기 상태를 포함한 전체 시스템의 검증 완료를 뜻하지는 않습니다. 이 문서는 새 정책을 확정하지 않습니다.

## Initial Non Goals and Current Scope

- 최초에는 다중 테마를 즉시 구현하지 않기로 했지만, 후속 작업으로 세 테마가 구현되었습니다. 초기 비목표는 현재의 다중 테마 금지 규칙이 아닙니다.
