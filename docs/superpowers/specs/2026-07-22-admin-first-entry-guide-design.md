# 어드민 첫 진입 가이드 모달 설계

작성일: 2026-07-22

## 1. 결정 요약

기본 온보딩을 완료한 사용자가 어드민에 처음 진입하면 3단계 스테퍼 모달을 자동으로 노출합니다.

- 별도 안내 페이지를 만들지 않습니다.
- 세 단계를 한 화면에 동시에 노출하지 않습니다.
- 사용자는 `이전`과 `다음`으로 한 단계씩 이동합니다.
- 마지막 단계의 Primary 버튼은 `첫 선물 담기`입니다.
- 모든 단계에서 `관리 화면 먼저 둘러보기`를 선택할 수 있습니다.
- 안내 이미지는 외부 사진이나 생성형 이미지가 아니라 실제 서비스 UI 스타일을 이용한 비작동 UI 비네트로 구현합니다.
- 사용자가 가이드를 완료하거나 명시적으로 닫으면 계정의 완료 시각을 저장합니다.
- 완료 이후에는 자동 노출하지 않지만 어드민 메뉴의 `사용 가이드`로 같은 모달을 다시 열 수 있습니다.

이 구조는 별도 경로와 리다이렉트 없이 현재 어드민 화면 위에서 작동하므로, 사용자가 안내를 건너뛰었을 때도 즉시 관리 화면을 이해할 수 있습니다.

### 1.1 확인된 근거

- `app/admin/layout.tsx`는 모든 어드민 경로를 감싸며 인증과 기본 온보딩 상태를 이미 조회합니다.
- `app/admin/wishes/page.tsx`에는 상품 링크 자동 채움 안내와 `create-wish` 진입점이 있습니다.
- `components/public-wishlist-view.tsx`는 `themeId` 기반 공개 화면과 선물 카드 스타일을 제공합니다.
- `app/admin/copy-public-link-button.tsx`에는 링크 복사 완료 상태와 토스트가 구현되어 있습니다.
- `package.json`에는 `radix-ui`가 설치되어 있고 lockfile에는 Radix Dialog 의존성이 확인됩니다.
- Wishes의 공식 How it works는 상품 추가, 링크 공유, 선물 확인을 실제 상품과 제품 화면으로 설명합니다: https://wishes.app/
- Giftster의 Quick Start Guide는 각 행동을 실제 등록·공유 화면과 함께 제시합니다: https://www.giftster.com/quick-start-guide/
- Appcues의 온보딩 사례는 첫 핵심 행동을 빠르게 경험시키고 과도한 선행 설명을 줄이는 패턴을 권장합니다: https://www.appcues.com/blog/best-user-onboarding-examples

## 2. 목적과 성공 기준

### 2.1 목적

서비스 기능 전체를 다시 설명하지 않고, 기본 온보딩을 마친 사용자가 첫 선물을 등록하도록 유도합니다. 공개 페이지 확인과 링크 공유는 첫 선물 등록 이후 이어질 행동으로 짧게 예고합니다.

### 2.2 성공 기준

- 기본 온보딩을 완료했고 가이드 완료 시각이 없는 사용자는 어떤 어드민 경로에 진입해도 모달을 한 번 봅니다.
- 완료 또는 건너뛰기 이후 다른 브라우저와 기기에서도 자동 노출되지 않습니다.
- 사용자는 모달 안에서 세 단계를 순서대로 이동할 수 있습니다.
- `첫 선물 담기`는 가이드 완료 저장 후 `/admin/wishes?create=1#create-wish`로 이동합니다.
- `관리 화면 먼저 둘러보기`, 닫기 버튼, Escape는 가이드 완료 저장 후 현재 화면을 유지합니다.
- 어드민 메뉴의 `사용 가이드`는 완료 여부와 관계없이 모달을 다시 엽니다.
- 키보드, 스크린 리더, 모바일 터치 환경에서 동일한 흐름을 사용할 수 있습니다.

## 3. 노출 대상과 완료 규칙

### 3.1 자동 노출 대상

다음 조건을 모두 만족할 때 자동으로 엽니다.

- 인증된 사용자입니다.
- 기본 온보딩이 완료되었습니다.
- `profiles.onboarding_guide_completed_at` 값이 없습니다.

현재 `app/admin/layout.tsx`가 모든 어드민 경로를 감싸고 기본 온보딩 상태를 확인하므로, 같은 레이아웃에서 가이드 상태를 조회하고 모달의 `initialOpen` 값을 결정합니다.

### 3.2 완료로 처리하는 행동

다음 행동은 모두 명시적인 완료 또는 건너뛰기로 간주합니다.

- 마지막 단계에서 `첫 선물 담기` 선택
- `관리 화면 먼저 둘러보기` 선택
- 우측 상단 닫기 버튼 선택
- Escape 키로 닫기

배경 오버레이 클릭은 모달을 닫지 않습니다. 계정 기준 완료 상태가 영구 저장되므로 실수로 배경을 눌러 안내를 건너뛰는 일을 방지합니다.

### 3.3 다시 보기

어드민 메뉴에 `사용 가이드` 항목을 추가합니다. 메뉴를 선택하면 현재 경로와 기존 검색 조건은 유지하고 URL 검색 파라미터에 `guide=1`만 추가합니다.

모달을 닫으면 `guide` 파라미터만 제거하고 나머지 경로와 검색 파라미터는 보존합니다. 다시 보기로 연 모달도 항상 첫 단계부터 시작합니다.

## 4. UX 흐름

```text
기본 온보딩 완료
→ 어드민 진입
→ 서버에서 가이드 완료 상태 조회
→ 미완료면 1단계 모달 자동 열림
→ 다음 / 이전 또는 모바일 스와이프로 단계 이동
→ 3단계에서 첫 선물 담기
→ 완료 시각 저장
→ /admin/wishes?create=1#create-wish 이동

또는

모달에서 관리 화면 먼저 둘러보기 / 닫기 / Escape
→ 완료 시각 저장
→ 현재 어드민 화면 유지

이후

어드민 메뉴의 사용 가이드
→ 같은 모달을 1단계부터 다시 열기
```

## 5. 모달 구조

### 5.1 공통 헤더

- 제목: `이제 위시리스트를 만들어볼까요?`
- 진행 표시: `01 / 03`, `02 / 03`, `03 / 03`
- 우측 상단 닫기 버튼: 접근성 이름 `안내 닫기`
- 현재 단계를 나타내는 진행 점 3개

진행 점만으로 상태를 전달하지 않고 숫자 텍스트를 함께 노출합니다.

### 5.2 단계별 내용

#### 1단계: 갖고 싶은 선물을 담아요

문구:

> 선물 링크를 넣으면 이미지, 이름, 가격을 빠르게 채울 수 있어요.

UI 비네트:

- 상품 링크가 입력된 URL 필드
- `정보 불러오기` 버튼
- 자동으로 채워진 상품명, 가격, 작은 썸네일 영역
- 실제 입력 컨트롤처럼 보이지만 포커스와 클릭은 받지 않음

#### 2단계: 친구에게 보일 페이지를 확인해요

문구:

> 등록한 선물이 친구들에게 어떻게 보이는지 미리 확인해보세요.

UI 비네트:

- 모바일 프레임 안의 공개 위시리스트 일부
- 선물명, 목표 금액, 진행 상태
- 사용자가 기본 온보딩에서 선택한 공개 테마 색상 적용
- 실제 참여 폼과 공유 버튼은 포함하지 않음

#### 3단계: 링크를 보내고 마음을 기다려요

문구:

> 위시리스트 링크를 공유하면 친구가 로그인 없이 마음을 보낼 수 있어요.

UI 비네트:

- 사용자의 실제 위시리스트 slug가 포함된 공개 URL
- 체크 아이콘이 표시된 `링크 복사` 완료 상태
- 짧은 축하 메시지 알림 카드 한 개
- 복사 버튼처럼 보이지만 실제 클립보드 동작은 하지 않음

### 5.3 하단 탐색

- 모든 단계 왼쪽: `관리 화면 먼저 둘러보기`
- 1단계 오른쪽: `다음`
- 2단계 오른쪽: `이전`, `다음`
- 3단계 오른쪽: `이전`, `첫 선물 담기`

1단계와 2단계의 `다음`은 서버 상태를 변경하지 않습니다. 단계 이동 상태는 브라우저 메모리에만 두며 새로 열면 1단계부터 시작합니다.

## 6. 시각 디자인

### 6.1 방향

어드민의 차분한 레이아웃 위에 공개 위시리스트의 네오브루탈리즘을 작은 강조 영역으로 가져옵니다. 모달 전체를 과도하게 장식하지 않고 UI 비네트와 Primary 버튼에만 브랜드 성격을 집중합니다.

- 모달 표면: 흰색 또는 `brand-paper`
- 모달 외곽: 굵은 `brand-ink` 테두리와 단단한 오프셋 그림자
- 제목: 큰 굵은 산세리프
- 강조색: 기존 `brand-blush`, `brand-yellow`, `brand-purple`, `brand-teal` 토큰 안에서 사용
- 그라데이션, 3D 렌더, 캐릭터 일러스트 사용 안 함
- 외부 이미지 다운로드와 생성형 이미지 에셋 사용 안 함

근거가 되는 기존 스타일은 `app/globals.css`의 브랜드 토큰과 `pixel-board`, `pixel-card`, `sticker-label`이며, 공개 페이지 스타일은 `app/public-themes.css`의 테마 변수를 사용합니다.

### 6.2 UI 비네트 구현 원칙

- 실제 등록 화면, 공개 카드, 링크 복사 화면의 필드명과 스타일 토큰을 사용합니다.
- 실제 폼이나 공개 페이지 전체 컴포넌트를 모달 안에 삽입하지 않습니다.
- 비네트는 전용 presentational component이며 네트워크 요청, 폼 제출, 링크 이동을 수행하지 않습니다.
- 비네트 컨테이너는 `aria-hidden="true"`, `pointer-events-none`, `select-none`으로 처리합니다.
- 단계 제목과 설명이 비네트의 의미를 텍스트로 제공하므로 별도 대체 텍스트를 중복 제공하지 않습니다.

### 6.3 화면 크기

데스크톱:

- 최대 너비 약 760px
- 비네트 높이 약 240-280px
- 하단 탐색은 한 줄 유지

모바일:

- 좌우 8px 이상의 여백을 둔 거의 전체 화면 모달
- 최대 높이 `100dvh - 16px`
- 비네트 높이 약 180-220px
- 설명과 탐색 영역이 작은 화면에서 잘리지 않도록 내부 스크롤 허용
- `첫 선물 담기`와 `다음` 버튼은 한 줄 레이블 유지

## 7. 단계 전환과 모션

- `다음`: 현재 콘텐츠가 왼쪽으로 8px 이동하며 사라지고 다음 콘텐츠가 오른쪽에서 나타남
- `이전`: 반대 방향으로 전환
- 전환 시간: 150-200ms
- 애니메이션 대상: `transform`, `opacity`만 사용
- `prefers-reduced-motion: reduce` 환경에서는 즉시 전환
- 자동 재생과 자동 단계 이동은 사용하지 않음

모바일에서는 좌우 스와이프를 보조 수단으로 제공합니다.

- 터치 이동 거리가 48px 이상일 때만 단계 이동
- 첫 단계에서 오른쪽 스와이프, 마지막 단계에서 왼쪽 스와이프는 무시
- 스와이프가 없어도 모든 기능을 버튼과 키보드로 사용할 수 있음
- 추가 애니메이션 라이브러리는 설치하지 않음

## 8. 기술 구조

### 8.1 데이터 모델

`profiles` 테이블에 nullable timestamp를 추가합니다.

```text
onboarding_guide_completed_at timestamp null
```

Drizzle 필드명:

```text
onboardingGuideCompletedAt
```

완료 상태는 브라우저 저장소가 아니라 계정 DB에 저장합니다. 동일 사용자가 다른 브라우저나 기기로 접속해도 중복 자동 노출되지 않습니다.

마이그레이션 시점에 이미 `onboarding_completed_at`이 있는 기존 프로필은 해당 시각을 `onboarding_guide_completed_at`에 백필합니다. 따라서 배포 전에 어드민을 사용하던 기존 사용자에게 새 가이드가 갑자기 자동 노출되지 않습니다. 배포 이후 기본 온보딩을 완료하는 새 프로필은 가이드 완료 시각을 `NULL`로 유지하고 첫 어드민 진입 때 모달을 봅니다.

### 8.2 서버 상태 조회

기존 `getOnboardingState` 반환값을 확장합니다.

```text
isComplete
wishlistSlug
wishlistThemeId
guideCompletedAt
```

`app/admin/layout.tsx`는 이미 사용자 인증과 기본 온보딩 완료를 확인하고 있습니다. 같은 서버 렌더 과정에서 `guideCompletedAt`과 비네트에 필요한 slug, theme ID를 읽어 클라이언트 모달에 전달합니다.

### 8.3 완료 처리 API

새 Route Handler:

```text
POST /api/admin/onboarding-guide/complete
```

책임:

- Auth.js 세션 확인
- 인증 사용자의 프로필만 갱신
- 첫 완료 시각을 저장하고 재호출 시 기존 시각을 보존
- 여러 번 호출해도 성공하는 idempotent API
- 성공 시 JSON `200`
- 세션 만료 시 JSON `401`
- 예상하지 못한 저장 실패 시 JSON `500`

클라이언트가 완료 API 성공 후 이동 또는 닫기를 수행합니다.

`첫 선물 담기`는 `/admin/wishes?create=1#create-wish`로 이동합니다. `create=1`은 이미 선물이 있는 사용자가 `사용 가이드`를 다시 열어 CTA를 눌러도 네이티브 `<details>` 등록 패널을 확실히 펼치기 위한 서버 렌더 신호이며, hash는 해당 패널로 스크롤하는 역할만 담당합니다.

### 8.4 클라이언트 컴포넌트

예상 컴포넌트 경계:

```text
AdminGuideDialog
├── AdminGuideProgress
├── AdminGuideStep
│   └── GuideStepVisual
└── AdminGuideActions
```

- `AdminGuideDialog`: 열림 상태, 현재 단계, 완료 요청, 키보드와 스와이프 제어
- `AdminGuideProgress`: 숫자와 진행 점 표시
- `AdminGuideStep`: 단계 제목과 설명
- `GuideStepVisual`: 3종 비작동 UI 비네트
- `AdminGuideActions`: 이전, 다음, 첫 선물 담기, 관리 화면 둘러보기

Radix Dialog를 사용합니다. 현재 `radix-ui` 패키지와 `@radix-ui/react-dialog` 의존성이 설치되어 있으므로 새 모달 라이브러리는 추가하지 않습니다.

### 8.5 사용 가이드 메뉴

현재 `app/admin/admin-shell-nav.tsx`의 데스크톱·모바일 메뉴에 `사용 가이드` 항목을 추가합니다.

- 현재 pathname과 search params를 유지합니다.
- `guide=1`만 추가해 모달을 엽니다.
- 모달을 닫을 때 `guide`만 제거합니다.
- URL로 상태를 표현하므로 새로고침과 직접 링크에서도 다시 보기가 동작합니다.

## 9. 상태 전이

```text
closed
→ automatic open when guideCompletedAt is null
→ step 1

step 1
→ next → step 2
→ skip / close / Escape → completing

step 2
→ previous → step 1
→ next → step 3
→ skip / close / Escape → completing

step 3
→ previous → step 2
→ first gift → completing
→ skip / close / Escape → completing

completing
→ success + first gift → /admin/wishes?create=1#create-wish
→ success + skip/close → closed on current page
→ failure → current step stays open and error message shown
```

완료 요청 중에는 완료 관련 버튼과 닫기 동작을 잠시 비활성화해 중복 요청을 방지합니다. API 자체도 idempotent하게 구현하여 네트워크 재시도에 안전하게 합니다.

## 10. 오류 처리

- 완료 저장이 실패하면 모달을 닫거나 이동하지 않고 현재 단계를 유지합니다.
- 저장 중에는 버튼에 `처리 중...` 상태를 표시합니다.
- `401`이면 `로그인이 만료되었습니다. 다시 로그인해주세요.`를 보여주고 로그인 화면으로 이동할 수 있게 합니다.
- `500` 또는 네트워크 오류면 `안내 상태를 저장하지 못했어요. 다시 시도해주세요.` 토스트를 표시합니다.
- 단계 이동은 서버 요청이 없으므로 네트워크 오류와 무관하게 동작합니다.
- UI 비네트는 외부 이미지와 API에 의존하지 않으므로 로딩 실패 상태가 없습니다.

## 11. 접근성

- Radix Dialog의 포커스 트랩, 제목·설명 연결, 포커스 복원을 사용합니다.
- 첫 자동 노출 시 모달 제목 또는 첫 번째 주요 버튼으로 포커스를 이동합니다.
- 현재 단계 변경을 `aria-live="polite"`로 알립니다.
- 진행 점은 장식으로 처리하고 `01 / 03` 형태의 텍스트 진행 정보를 제공합니다.
- 닫기 버튼에 `안내 닫기` 접근성 이름을 제공합니다.
- 비네트 안의 가짜 필드와 버튼은 포커스 순서와 접근성 트리에서 제외합니다.
- Escape는 완료 저장을 시도하며, 저장 실패 시 닫기를 취소하고 오류를 알립니다.
- 배경 콘텐츠는 모달이 열린 동안 포인터와 키보드로 조작할 수 없습니다.
- 모든 텍스트와 버튼은 WCAG AA 대비를 확인합니다.

## 12. 테스트 전략

### 12.1 데이터와 서비스 테스트

- 가이드 미완료 프로필의 완료 시각 저장
- 이미 완료된 프로필에 재요청해도 기존 완료 시각 보존
- 마이그레이션이 기존 온보딩 완료 프로필을 가이드 완료 상태로 백필
- 배포 이후 생성되는 프로필의 가이드 완료 시각은 `NULL` 유지
- 다른 사용자의 프로필을 변경하지 않음
- 기본 온보딩 미완료 상태 처리
- DB 오류를 예상 가능한 실패로 변환

### 12.2 Route Handler 테스트

- 인증된 사용자 요청은 `200`
- 인증되지 않은 요청은 `401`
- 반복 요청도 `200`
- 저장 실패는 `500`

### 12.3 UI 상태 테스트

- `initialOpen=true`일 때 1단계 자동 노출
- 다음과 이전 경계 처리
- 첫 단계 이전 이동과 마지막 단계 다음 이동 방지
- 48px 이상 모바일 스와이프만 단계 이동
- `prefers-reduced-motion`에서 전환 애니메이션 제거
- 완료 API 실패 시 모달 유지
- 완료 API 성공 후 올바른 이동 또는 닫기
- 다시 보기 시 1단계부터 시작
- `guide` 검색 파라미터만 추가·제거하고 다른 파라미터 보존

### 12.4 수동 검증

- 데스크톱 어드민 모든 경로에서 첫 자동 노출
- 모바일 세로 화면에서 콘텐츠와 하단 버튼이 잘리지 않음
- 키보드 Tab 순서, Shift+Tab, Enter, Escape
- 스크린 리더의 제목, 설명, 단계 변경 안내
- 첫 선물 담기 후 선물 추가 패널 노출
- 다른 브라우저 또는 로그아웃·재로그인 후 중복 자동 노출 없음
- 사용 가이드 메뉴를 통한 재호출

### 12.5 실행 명령

```text
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

현재 로컬 Node `v20.15.0`에서는 설치된 Vitest/Vite 조합의 ESM 호환 문제로 `pnpm test`가 설정 로딩 단계에서 실패하는 기존 환경 문제가 있습니다. 구현 검증 시 호환되는 Node 런타임으로 테스트하거나, 실패 원인이 이번 기능과 무관함을 명시적으로 기록합니다.

## 13. 구현 순서

1. DB 필드와 마이그레이션을 추가합니다.
2. 온보딩 상태 조회와 idempotent 완료 저장을 구현하고 서비스 테스트를 작성합니다.
3. 완료 Route Handler를 구현하고 인증·오류 테스트를 작성합니다.
4. Radix 기반 가이드 모달과 단계 상태를 구현합니다.
5. 3종 UI 비네트와 반응형 스타일을 구현합니다.
6. 어드민 레이아웃의 자동 노출과 메뉴의 다시 보기를 연결합니다.
7. 접근성, 모바일, 전체 명령을 검증합니다.

## 14. 제외 범위

이번 기능에는 다음을 포함하지 않습니다.

- 단계별 완료 상태의 DB 저장
- 사용자의 실제 선물 데이터에 따른 가이드 내용 변경
- 선물 등록 이후 자동으로 2단계나 3단계를 다시 띄우는 기능
- 분석 이벤트와 전환 퍼널 대시보드
- 외부 이미지, 사진, AI 생성 이미지
- 자동 재생, 자동 단계 이동
- 공개 위시리스트 컴포넌트 전체를 모달에 삽입하는 방식
- 새로운 모달 또는 애니메이션 패키지 설치

## 15. 완료 기준

- 최초 어드민 진입 시 3단계 모달이 자동으로 열립니다.
- 사용자는 이전, 다음, 모바일 스와이프로 단계를 이동할 수 있습니다.
- 각 단계에는 실제 서비스 스타일과 연결된 비작동 UI 비네트가 표시됩니다.
- 완료 또는 건너뛰기 상태가 계정 DB에 저장됩니다.
- 완료 이후 어떤 기기에서도 자동 재노출되지 않습니다.
- `사용 가이드` 메뉴로 언제든 같은 모달을 다시 열 수 있습니다.
- Primary CTA는 첫 선물 등록 패널로 이동합니다.
- 배경 클릭으로 실수로 영구 건너뛰기 되지 않습니다.
- 키보드와 스크린 리더로 전체 흐름을 사용할 수 있습니다.
- typecheck, lint, test, build 결과가 기록됩니다.
