# 확인창 (ConfirmDialog)

이 문서는 되돌리기 어렵거나 결과가 큰 행동 전에 띄우는 확인창의 모양과 문구 기준입니다. 브라우저 기본 `window.confirm`, `alert`, `prompt`는 새로 쓰지 않고 이 확인창을 씁니다.

## 언제 쓰나요

| 종류 | 쓰는 곳 | 확인 버튼 |
| --- | --- | --- |
| 위험 확인 (`tone="danger"`) | 계좌 삭제, 회원 탈퇴, 선물 삭제, 위시리스트 초기화, 온보딩 만 14세 미만 제출 | 빨간 채움 버튼 |
| 일반 확인 (`tone="default"`) | 메시지 숨기기 | 검은 채움 버튼 (`admin`) |

토스트로 충분한 결과 알림이나 되돌리기가 쉬운 행동에는 확인창을 띄우지 않습니다. 메시지 `숨김 해제`는 확인 없이 바로 복구합니다.

## 구성

- 컴포넌트: `components/ui/confirm-dialog.tsx`, Radix `AlertDialog` 기반입니다.
- 제목: 확인 문구의 질문입니다. 예: `계좌 정보를 삭제할까요?`, `정말 탈퇴할까요?`
- 설명: 질문 뒤에 오는 나머지 문장입니다. 무엇이 지워지는지, 되돌릴 수 있는지를 씁니다.
- 버튼 두 개: 왼쪽 취소(`cancelLabel`, 기본 `취소`, `admin-outline`), 오른쪽 확인 버튼입니다. 닫기(X) 버튼은 두지 않습니다.
- 확인 버튼 문구는 행동 이름으로 씁니다. `확인`, `예`는 쓰지 않습니다. 예: `삭제`, `탈퇴`.
- 여는 버튼: `triggerLabel`이 있으면 Button을 렌더합니다. `triggerVariant`를 생략하면 `danger`입니다. 메시지 숨기기는 목록의 기존 버튼과 같게 `subtle`을 넘깁니다.
- 폼을 제출하는 순간에 열어야 하면 트리거 없이 `open`과 `onOpenChange`로 제어합니다. 온보딩 만 14세 미만 확인이 이 방식입니다. 확인은 같은 `formId` 폼을 `requestSubmit`합니다.

## 모양

- 배경: `fixed inset-0 z-40 bg-black/45 backdrop-blur-[2px]` (관리자 안내와 같습니다)
- 상자: `w-[calc(100%-32px)] max-w-[400px] rounded-md border-2 border-ink bg-paper p-5 shadow-[5px_5px_0_var(--ink-deep)] sm:p-6`
- 제목: `text-lg font-black break-keep text-ink`
- 설명: `mt-2 text-sm font-medium leading-6 break-keep text-zinc-600`
- 버튼 줄: `mt-5 flex gap-2 sm:justify-end`. 모바일에서는 두 버튼이 `flex-1 h-11`로 반씩 차지하고, `sm` 이상에서는 내용 너비 `h-9`입니다.
- 위험 확인 버튼: Button 변형 `danger-solid`. `h-9 rounded-md border border-danger bg-danger px-3.5 text-sm font-semibold whitespace-normal text-white transition-colors hover:bg-[#991b1b]`

## 동작

- 열리면 포커스는 취소 버튼(`cancelLabel`)에 갑니다. 위험한 버튼에 기본 포커스를 두지 않습니다.
- `Esc`는 취소와 같습니다. 바깥을 눌러도 닫히지 않습니다(AlertDialog 기본).
- 확인을 누르면 `formId` 폼을 `requestSubmit`하고, 응답이 올 때까지 창을 열어 둔 채 두 버튼을 잠급니다. 확인 버튼 문구는 `pendingLabel`로 바뀝니다.
- 트리거로 연 창이 닫히면 포커스는 그 버튼으로 돌아갑니다.
- 제어 모드에는 트리거가 없어서 닫힐 때 포커스를 트리거로 되돌리지 않습니다. 온보딩은 취소(`연도 고치기`)나 `Esc` 뒤에 달력을 열고 `연도 선택`으로 포커스를 옮기며, 제출하지 않습니다.

## 문구 위치

문구는 [copy.ts](../../../src/lib/design/copy.ts)에 둡니다. 계좌 삭제·탈퇴·선물 삭제·메시지 숨기기·위시리스트 초기화는 기존 확인 문구를 제목과 설명으로 나누기만 하고 내용은 바꾸지 않습니다. 온보딩 만 14세 미만은 브라우저 버튼 이름(`확인`, `취소`)을 말하던 문장을 아래 문구로 바꿨습니다.

| 화면 | 제목 | 설명 | 취소 | 확인 | 진행 중 |
| --- | --- | --- | --- | --- | --- |
| 계좌 삭제 | 계좌 정보를 삭제할까요? | 은행, 예금주, 계좌번호가 모두 지워지고 되돌릴 수 없어요. 공개 위시리스트에도 계좌가 보이지 않아요. | 취소 | 삭제 | 삭제하는 중… |
| 회원 탈퇴 | 정말 탈퇴할까요? | 계정, 위시리스트, 선물, 받은 메시지, 모인 금액 기록, 계좌 정보가 바로 모두 삭제되고 되돌릴 수 없어요. 탈퇴한 뒤에는 다른 사람이 같은 공개 주소를 쓸 수 있어서, 예전에 공유한 링크가 다른 사람의 위시리스트로 열릴 수 있어요. | 취소 | 탈퇴 | 탈퇴하는 중… |
| 선물 삭제 | 이 선물을 삭제할까요? | 모인 금액이 있으면 `이 선물에 모인 금액 기록도 함께 삭제되고 되돌릴 수 없어요. 받은 메시지는 메시지함에 남아요.` 없으면 `삭제하면 되돌릴 수 없어요.` | 취소 | 삭제 | 삭제하는 중… |
| 위시리스트 초기화 | 위시리스트를 초기화할까요? | 등록한 선물, 받은 메시지, 모인 금액 기록이 모두 삭제되고 되돌릴 수 없어요. 프로필, 공개 주소, 테마, 계좌 안내는 유지돼요. | 취소 | 초기화 | 초기화하는 중… |
| 메시지 숨기기 | 이 메시지를 숨길까요? | 금액이 있으면 `함께 보낸 마음 금액은 모인 금액에서 빠지고, 숨긴 메시지 목록에서 복구할 수 있어요.` 없으면 `숨긴 메시지 목록에서 복구할 수 있어요.` | 취소 | 숨기기 | 숨기는 중… |
| 온보딩 만 14세 미만 | `{연도}년생이 맞나요?` | 만 14세 미만은 가입할 수 없어서, 이대로 제출하면 로그인 정보가 바로 삭제돼요. | 연도 고치기 | 이 생일로 제출 | 제출하는 중… |
