# 위시 카드

코드 대조일: 2026-11-04 (`main` @ `d26141e`, PR #20 반영)

[디자인 가이드](../README.md) · [기초 규칙](../foundations.md) · [폼](form.md) · [피드백](feedback.md)

이 문서는 선물 하나를 보여 주는 카드의 기존 표현을 재사용하기 위한 안내입니다. 친구는 카드에서 무슨 선물인지, 얼마나 모였는지, 지금 마음을 보탤 수 있는지를 확인하고, 소유자는 같은 정보를 관리용으로 압축해 봅니다. 현재 구현, 유지할 규칙, 미결정 개선을 구분하며, 시각 변경 제안은 승인 전까지 규칙이 아닙니다. 이번 작성은 정적 코드 대조와 PR #18 캡처 확인이며 접근성·모든 테스트를 새로 검증한 기록은 아닙니다.

## 사용 상황

| 위치 | 경로 | 구현 | 시각 표현 |
| --- | --- | --- | --- |
| 공개 위시리스트 | `/wishlist/[slug]` | [공개 뷰](../../../components/public-wishlist-view.tsx)의 내부 `PublicWishCard` | 선택 공개 테마(`pixel_y2k`, `mono_bw`, `soft_pastel`) |
| 샘플 | `/sample?theme=` | 같은 `PublicWishCard`, 데이터는 [샘플](../../../app/sample/page.tsx) | 세 테마. 저장하지 않음 |
| 관리자 선물 목록 | `/admin/wishes` | [관리자 선물](../../../app/admin/wishes/page.tsx)의 `WishItemEditor`, `WishThumbnail` | 관리자 차분한 표현. 공개 테마 미적용 |
| 관리자 대시보드 최근 선물 | `/admin` | [대시보드](../../../app/admin/page.tsx)의 `DashboardQueueRow` | 관리자 표현. 상태별 색 없음 |

홈의 예시 진행 카드(`app/page.tsx`)는 고정 브랜드 소개 화면이며 이 패턴의 범위가 아닙니다.

## 현재 구현과 근거

### 상태 판정과 라벨

판정과 문구의 원본은 [status.ts](../../../src/lib/wish-item/status.ts)입니다.

- `isWishComplete(status, progress)`: `fulfilled`이거나 진행률 100% 이상이면 완료.
- `getDisplayedWishStatus(status, progress)`: 화면에 보일 상태. 진행률 100% 이상인 `open`은 `fulfilled`로 표시하고, `paused`·`hidden`은 진행률과 관계없이 저장된 상태를 유지.
- `getWishStatusLabel(status, progress?)`: 위 표시 상태의 문구. 진행률을 넘기지 않으면 저장된 상태의 문구.

| 저장 상태·조건 | 공개 카드 | 관리자 목록 배지 | 대시보드 최근 선물 |
| --- | --- | --- | --- |
| `open`, 100% 미만 | "마음 모으는 중", 참여 폼 표시 | "마음 모으는 중", 초록 | 문구만 |
| `open`, 100% 이상 | "완료", 참여 폼 없음 | "완료", 파랑 | "완료" 문구만 |
| `fulfilled` | "완료", 참여 폼 없음 | "완료", 파랑 | 문구만 |
| `paused` | "잠시 멈춤", 참여 폼 없음 | "잠시 멈춤", 주황(100%여도) | 문구만 |
| `hidden` | 공개 목록에서 제외 | "숨김", 회색(100%여도) | 문구만 |

- 공개 참여 폼은 `canFund = status === "open" && !isComplete`일 때만 나옵니다. 서버 저장도 `open`을 확인하며 UI 표시가 서버 검증을 대신하지 않습니다. 근거: [form.md](form.md#입력과-검증).
- `hidden`은 [공개 조회 서비스](../../../src/lib/public-wishlist/service.ts)에서 제외됩니다.
- 관리자 목록 배지는 `getDisplayedWishStatus`로 표시 상태를 따릅니다. 반면 **상태 필터 탭과 수정 폼의 상태 선택지는 저장된 `status`** 를 씁니다. 100%인 `open` 선물은 배지가 "완료"여도 "마음 모으는 중" 필터에 남고 수정 폼에서도 `open`으로 선택돼 있습니다.
- 대시보드 최근 선물은 `getWishStatusLabel(status, progress)` 문구만 표시하며 상태별 색이 없습니다.

### 공개 카드 구성

```
article.gift-card-shell.theme-card
├─ 이미지 영역: 이미지(4:3) 또는 GiftFallback "GIFT"
├─ 본문: .pub-pill "NO. n" · 상태 라벨 · 이름(줄 수 제한 없음) · 설명(선택)
├─ 진행 패널: 모인 금액 / 목표. 목표가 있을 때만 .pub-progress와 "N%". 없으면 "목표 금액 없음". "선물 링크 보기"(productUrl 있을 때)
└─ 참여 영역 "이 선물에 마음 보태기"(canFund일 때만)
```

- 목표가 있는 카드의 진행률은 `.pub-progress`입니다. 완료 카드도 같은 채움색을 쓰고, 목표가 없으면 막대와 백분율은 표시하지 않습니다. 카드·라벨·버튼은 [foundations.md](../foundations.md#공개-테마와-표현)의 공개 표현을 사용합니다.
- "선물 링크 보기"는 상태와 관계없이 `productUrl`이 있으면 표시됩니다.
- 375px은 이미지, 본문, 진행 패널, 참여 영역 순의 1단, `lg` 이상은 이미지와 본문·진행 패널의 2단입니다.

### 관리자 목록 구성

```
details > summary
├─ WishThumbnail 48×48: 이미지 또는 "선물" 텍스트
├─ 이름(한 줄 말줄임) · 상태 배지(점 포함)
├─ "₩모인 / ₩목표" 또는 "목표 금액 없음"
├─ 진행 바 h-1.5 (track zinc-100, fill teal)
└─ 수정 / 닫기
```

배지 색은 [관리자 선물](../../../app/admin/wishes/page.tsx)에 직접 지정돼 있습니다.

| 표시 상태 | 배경 | 글자 | 점 |
| --- | --- | --- | --- |
| 진행 중 `open` | `#ecfdf5` | `#047857` | `#10b981` |
| 완료 `fulfilled`·100% `open` | `#eff6ff` | `#1d4ed8` | `#3b82f6` |
| 잠시 멈춤 `paused` | `#fff7ed` | `#9a3412` | `#f97316` |
| 숨김 `hidden` | `#f4f4f5` | `zinc-600` | `zinc-400` |

## 작업 시 유지할 규칙

1. 상태 문구는 `getWishStatusLabel`, 표시 상태는 `getDisplayedWishStatus`를 사용합니다. 화면에서 진행률로 완료를 다시 계산하지 않습니다. 근거: 위 status.ts.
2. `fulfilled` 또는 100% 이상은 "완료"이고 공개 참여 폼을 닫습니다. `paused`·`hidden`은 진행률과 관계없이 소유자가 고른 상태를 유지합니다(2026-11-03 채영 결정).
3. 완료 색은 관리자 목록 배지에만 사용합니다. 대시보드 최근 선물에는 상태별 색을 추가하지 않습니다(PR #20 범위).
4. 필터와 수정 폼은 저장된 상태 기준을 유지합니다. 배지 표시를 이유로 필터 결과나 폼 기본값을 바꾸지 않습니다.
5. 공개 카드의 시각 차이는 테마 토큰과 기존 `.pub-*` 표현으로만 만듭니다. 관리자 배지 색을 공개 카드에 가져오지 않습니다. 근거: [foundations.md](../foundations.md#토큰의-소유-범위).
6. 테마 키는 DB와 `/sample?theme=`에서 사용하므로 바꾸지 않습니다.

## 차이와 미결정

현재 구현의 차이는 기록이며 수정 완료 조건이 아닙니다. 🟡 제안은 승인 전까지 적용하지 않고, 기존 `--pub-*`·`--brand-*` 값만 사용하는 안입니다.

| 현재 차이 | 🟡 제안 (미승인) |
| --- | --- |
| 완료·멈춤 카드가 라벨 외에는 `open`과 같은 모양이고, 100% 진행 바도 같은 색 | ❌ P1·P2 적용 안 함(2026-11-04 채영 결정, 현행 유지). 원안: P1. 완료 시 라벨을 `.pub-pill-alt`로 강조하고 진행 바 채움을 `--pub-point`로. P2. `paused`는 본문·이미지를 약하게 흐리게(라벨·링크 제외) |
| 참여 영역이 통째로 빠져 카드 높이가 상태마다 다름 | ✅ P3 적용 결정(2026-11-04 채영, 구현 전). P3. 참여 영역 자리에 한 줄 안내를 `--pub-sub`로 표시. 문구(기획 봇 제안): 완료 "마음이 다 모였어요. 고마워요!", 멈춤 "지금은 잠시 마음을 받지 않아요." 모든 화면 폭에서 같은 문구(짧은 문구 사용 안 함, 2026-11-04 채영 결정) |
| 공개 카드 이름 줄 수 제한 없음. 375px에서 10줄 이상 가능(`wishlist-mono_bw-375-mixed.png`), 관리자는 한 줄 말줄임 | ❌ P4 적용 안 함(2026-11-04 채영 결정, 현행 유지). 원안: P4. 375px 3줄, `lg` 2줄 말줄임과 전체 이름 `title` |
| 이미지 없음 표시가 공개 "GIFT" 일러스트와 관리자 "선물" 텍스트로 다름 | ✅ P5: 관리자 썸네일도 "GIFT"로 통일(2026-11-04 채영 결정, 구현 전) |
| 진행 바가 공개 `.pub-progress`, 관리자 `h-1.5 teal`, 홈 예시까지 세 가지 | P6. 토큰 단계에서 검토(추천: 미룸) |
| 관리자 배지 색이 hex·zinc 직접 지정 | P7. 토큰 단계에서 이름 부여 검토(추천: 미룸) |
| 관리자 `WishItemEditor`가 진행률을 직접 계산(`calculateProgress`와 결과는 같음) | 별도 제안 없음 |
| 완료 카드에도 "선물 링크 보기" 표시 | ✅ 유지(2026-11-04 채영 결정) |
